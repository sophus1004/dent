# DENT 개발 원칙

코드를 두는 자리 · 학습 데이터에 대해 믿는 것 · 사람과 AI가 함께 만드는 약속

[아키텍처](#1-아키텍처-층과-경계) · [철학](#2-철학) · [기능](#3-기능-철학이-들어간-자리) · [규칙](#4-규칙-사람과-ai가-함께-만드는-방법) · [검증](#5-검증-믿지-말고-잰다) · [README](../README.md)

</div>

DENT는 한 사람이 방향을 정하고 AI 코딩 도구(Claude Code)가 코드를 쓰는 **바이브코딩**으로 만듭니다.
AI가 코드를 빨리 쓸수록, 무엇을 믿고 무엇을 하지 않는지, 그리고 **코드를 어디에 두는지**를 먼저 정해 두어야 결과가 흔들리지 않습니다.

| 장 | 적는 것 |
|---|---|
| 1. 아키텍처 | 코드를 어디에 두는가: 네 층 · 경계 · import 방향 · 파일마다 한 가지 일 |
| 2. 철학 | 학습 데이터에 대해 DENT가 믿는 것 |
| 3. 기능 | 그 믿음이 기능 어디에 들어가 있는가 |
| 4. 규칙 | 사람과 AI가 어떤 약속으로 함께 만드는가 |
| 5. 검증 | 결과 데이터를 어떻게 따로 재는가 |

코드 규칙의 원본은 AI 코딩 도구가 일할 때마다 읽는 작업 규칙 파일이고, 개발 과정의 기록이라 공개하지 않습니다.
이 문서는 그 가운데 공개할 원칙과, 그 원칙이 왜 그렇게 생겼는지를 옮겨 적은 것입니다.

## 1. 아키텍처: 층과 경계

바이브코딩에서 가장 먼저 정하고 가장 엄하게 지키는 것이 구조입니다.

AI는 코드를 빨리 쓰지만, 둘 자리를 정해 주지 않으면 같은 일을 여기저기 다시 만들고, 한 곳을 고치면 먼 곳이 깨집니다.
사람은 AI가 쓴 모든 줄을 읽을 수 없습니다. 대신 **자리**를 봅니다: "이 코드가 이 층, 이 파일에 있어도 되나."
층과 경계가 분명하면 검토는 이 질문 하나로 줄고, 잘못은 한 층 · 한 모듈 안에 머물며, 대화가 바뀌어도 AI는 같은 자리에 같은 일을 둡니다.

### 네 층

| 층 | 폴더 | 두는 것 |
|---|---|---|
| system | `src/dent/system/` | 모델 종류와 상관없이 모든 모듈이 쓰는 바탕: 설정 · DB · 작업 실행기 · 파일과 허깅페이스 읽기 · 외부 · 내장 모델 연결 · 도우미 엔진 · 내보내기 |
| modules | `src/dent/modules/<모듈>/` | 그 모델 종류에만 있는 데이터 모양과 규칙: 자기 표 · 칸 맞추기 · 진단 기준 · 고치기 (분류 `classification` · 검색 `retrieval`) |
| api | `src/dent/api/` | 시스템 API, 모든 API를 `/api/v1`로 모으기, 도메인 예외 → HTTP 바꾸기, 화면 파일 내주기 |
| web | `web/src/system/` · `web/src/modules/<모듈>/` | 화면. 백엔드와 같은 system · modules 구분 |

층 밖에는 조립 파일만 둡니다: 모든 표를 모으는 `models.py`, 앱을 만드는 `main.py`, 모든 작업을 모으는 `worker.py`,
실행 명령(`launcher.py` · `supervisor.py` · `server.py` · `model_server.py`). 조립 파일만 무엇이든 가져다 씁니다.

### 경계: "원본 → 줄"까지는 system, "줄 → 자기 데이터"부터는 모듈

system은 파일 · 허깅페이스 데이터셋을 열어 **줄(칸 이름: 값, 줄 번호)**로 내는 데까지 합니다.
그 줄을 문장과 라벨로 볼지, 질의와 문서로 볼지는 모듈이 정합니다.

예를 들어 같은 문장을 찾는 해시는 system이 만들지만, 같은 문장을 **중복**으로 볼지 **라벨 충돌**로 볼지는 모듈이 정합니다.
경계를 한 줄로 적어 두면 새 기능이 어느 쪽인지 다툴 일이 줄어듭니다.

### import 방향

```
main.py · models.py · worker.py     → 무엇이든 (조립)
api/router.py                       → api · system · modules (모듈 라우터를 모은다)
api/그 밖                           → system
modules/<모듈>/router.py            → 같은 모듈 · system
modules/<모듈>/그 밖                → 같은 모듈 · system (웹 프레임워크를 모른다)
system/                             → system 안에서만
```

- **모듈끼리는 서로를 모릅니다.** import도, 표 사이의 외래 키도 없습니다. 모듈 하나를 빼도 나머지는 깨지지 않습니다.
- **system은 위를 모릅니다.** system 코드는 모듈 · api를, system 표는 모듈 표를 가리키지 않습니다. 모듈 표는 system 표를 가리켜도 되고,
  데이터셋을 지우면 외래 키의 CASCADE가 모듈의 데이터를 함께 지웁니다.
- **공용은 system 한 곳.** 두 모듈 이상이 쓸 기능은 system에 한 번만 둡니다. 제3의 공용 폴더는 만들지 않습니다.

### 파일마다 한 가지 일

한 층 안에서도 파일마다 맡는 일과 하지 않는 일을 정해 둡니다. AI가 가장 자주 어기는 곳이 여기라서, 하지 않는 일을 함께 적습니다.

| 파일 | 하는 일 | 하지 않는 일 |
|---|---|---|
| `models.py` | 표. 칸마다 설명 주석, 자주 찾는 외래 키에 색인 | 업무 판단 |
| `schemas.py` | 입출력 모양. 입력은 앞뒤 공백을 떼고 길이를 잰다 | DB 접근 · 업무 판단 |
| `service.py` (와 같은 층의 파일) | 업무 규칙, 트랜잭션 확정, 규칙 위반은 한국어 문장의 도메인 예외 | HTTP · 상태 코드 |
| `router.py` | 받고, 넘기고, 돌려주기 | 쿼리 · 업무 판단 · 예외 잡기 |
| `jobs.py` | 요청 하나로 끝나지 않는 일(가져오기 · 분석 · 도우미)을 작업 실행기에 맡김 | — |

- 도메인 예외를 HTTP 상태로 바꾸는 일은 api의 표 **한 곳**에서 합니다. 표에 없는 예외는 500으로 드러납니다.
- 새 기능은 **아래층부터** 만듭니다: 표 → 마이그레이션 → 입출력 모양 → 업무 규칙 → API → 작업 → 테스트 → 화면.
  아래층이 먼저 있어야 위층이 추측으로 채우지 않습니다.

### 모듈 붙이기: 세 줄과 한 칸

모듈 하나는 백엔드 세 군데에 한 줄씩, 화면 목록에 한 칸으로 붙습니다. 빼면 이 자리만 지웁니다.

| 붙이는 곳 | 붙이는 것 |
|---|---|
| `api/router.py` | 모듈의 API 라우터 |
| `models.py` | 모듈의 표 |
| `worker.py` | 모듈의 작업 처리 함수 · 끊긴 작업의 뒷정리 · 처음 실행할 때 넣는 내장 예시 |
| `web/src/modules.ts` | 모듈의 화면(주소 · 사이드바 · 홈 칸 · 명령) |

다음 모듈인 생성(`generation`)도 이렇게 붙습니다.

### 기계가 지킨다

규칙을 사람의 기억에만 두면 AI도 사람도 어깁니다. 검사할 수 있는 규칙은 검사로 둡니다.

- **화면:** 빌드 전에 층 검사 스크립트가 돕니다. system이 modules를 가져다 쓰거나, 모듈끼리 가져다 쓰거나,
  정해진 두 파일 밖에서 modules를 가져다 쓰거나, 데이터를 HTML로 그리거나(`v-html`), 파일 맨 위에 한국어 설명이 없으면 빌드가 멈춥니다.
- **백엔드:** 아래 두 줄의 결과가 비어 있어야 합니다.

  ```bash
  grep -rn "dent.modules\|dent.api" src/dent/system
  grep -rn "dent.api" src/dent/modules
  ```

- **모양:** 줄 길이(100자) · 들여쓰기는 `ruff format`이 맞추고, import 순서 · 쓰지 않는 import · 흔한 버그는 `ruff check`가 봅니다.

'4장 규칙은 사고에서 나온다'의 "공통 기능(파일 읽기)을 한 모듈 안에 넣었다"가 이 경계를 한 줄로 적게 된 일입니다.

## 2. 철학

### 데이터가 먼저다

이름 그대로입니다. **D**ata **E**specially **N**eeds **T**idying.
좋은 학습 데이터는 라벨마다 양이 비슷하고, 한 건 한 건이 서로 다른 것을 가르치며, 거짓 정답이나 거짓 오답이 없습니다.
모델 구조나 학습 설정을 바꾸기 전에 이 상태를 만드는 것이 DENT의 일입니다.

### 결론 → 문제 → 고치기

분석 도구는 좋은 지표를 나열하는 것만으로는 쓰이지 않습니다. 화면은 보고서처럼 읽혀야 합니다.

- 맨 위에는 결론: `준비 안 됨 · 심각 2 · 주의 1`
- 그 아래 문제 줄: 등급 · 검사 · 값 · 영향 · 조치. 누르면 그 문제에 해당하는 데이터만 보입니다
- 마지막이 고치기

화면에는 문장을 쓰지 않고 낱말 · 숫자 · 기준 · 태그 · 짧은 버튼 이름만 씁니다. 데이터 자체(인용한 문장)만 예외입니다.

### 규칙은 모양만 본다

데이터가 뉴스인지 법령인지 매뉴얼인지 가정하지 않습니다. 전처리 규칙은 글의 **모양**만 봅니다:
반복(몇 문서에 나오나) · 자리(앞머리 · 꼬리) · 길이 · 구조 표지(제목 줄 · 번호 단위) · 메타 모양(이메일 · 웹 주소 · 저작권 표시).

"이 반복이 서명인가 내용인가"처럼 뜻을 봐야 하는 판단은 사람이 합니다. 도구는 보기를 보여 주고 제안만 합니다.

### 싼 판단부터: 규칙 → 판정 모델 → LLM

- 판단이 필요 없는 고치기(똑같은 문장의 여분 빼기, 목차만 있는 청크 표시)는 **규칙**이 합니다.
- 문장 하나하나의 판정(이 문장의 라벨, 이 문서가 질의의 답을 담았나)은 **판정 모델**이 합니다.
- **LLM**은 규칙과 판정 모델이 모두 애매한 것만 봅니다.

비용 때문만이 아닙니다. 규칙은 설명할 수 있고, 판정 모델은 빠르고, LLM은 느리고 비쌉니다. 각자 잘하는 곳에 둡니다.
판정 모델도 틀립니다. 그래서 판정 충돌을 풀거나 정답 없는 질의에 정답을 붙일 때는 **판정 모델과 LLM의 답이 같을 때만** 바꾸고,
엇갈리면 보류하거나 모름으로 둡니다. 빠진 정답 · 거짓 오답 제안은 아직 판정 모델 확인만으로 받고, 이 범위를 넓힐지는 정하는 중입니다(5장).

### AI는 제안하고 사람이 정한다, 모든 고치기는 되돌린다

- 판정 모델과 LLM의 결과는 제안입니다. 사람이 받아들여야 데이터가 바뀝니다.
- 도우미가 바로 고치는 것도 모두 변경 기록에 남기고, 카드 하나 또는 실행 전체 단위로 되돌립니다.
- 영구 삭제는 없습니다. 지운 것은 휴지통에 가고, 사람이 휴지통을 비울 때만 사라집니다.
- 되돌리기는 값 하나가 아니라 그 줄의 상태 전체를 돌립니다(예: 판정의 등급뿐 아니라 출처와 충돌 표시까지).

### 만든 데이터는 드러낸다

AI가 만든 문장과 질의는 출처(`synthetic`)로 가려 두고, 내보내는 파일에 출처 칸을 넣습니다.
이미 있는 데이터와 뜻이 거의 같은 것은 만들어도 버립니다. 베낀 데이터는 학습에 보탬이 적고 평가를 부풀립니다.

### 나누지 않는다

학습 · 검증 · 평가(train · valid · test)로 나누지 않고 모든 데이터를 한 덩어리로 정리합니다. 원본에 분할이 있어도 합칩니다.
나누기는 정리가 끝난 뒤, 내려받을 때의 일입니다. 그때는 같은 글 · 근접 중복 · 같은 원문의 청크를 한쪽에 모아야 새지 않습니다.

### 믿지 말고 잰다

기능이 된다는 것과 결과 데이터가 좋다는 것은 다릅니다.
일부러 문제를 심은 데이터로 가져오기부터 내보내기까지 직접 돌리고, 결과 파일은 앱 코드를 쓰지 않는 따로 된 검증기로 잽니다.
검증에서 찾은 문제는 고치고 테스트로 남깁니다(5장).

## 3. 기능: 철학이 들어간 자리

| 기능 | 하는 일 | 따르는 원칙 |
|---|---|---|
| 진단 | 검사마다 등급(통과 · 주의 · 심각)과 값을 한 줄로, 종합 상태를 맨 위에 | 결론 → 문제 → 고치기 |
| 뜻 분석 | 임베딩으로 근접 중복 · 오라벨 의심 · 의미 쏠림 · 기준 검색 점수 | 믿지 말고 잰다. 비싼 계산이라 사람이 누르거나 도우미를 시작할 때 만든다 |
| 제안 | 오라벨 의심 · 빠진 정답 · 거짓 오답을 [수락] · [유지] | AI는 제안, 사람이 정한다 |
| 반복 구간 | 여러 문서에 되풀이되는 문장 · 메타 모양을 틀로 묶어 보기와 함께 | 규칙은 모양만, 떼기 · 남김은 사람이 |
| 문서 나누기 | 구조 → 줄 → 문장 순서, 청크마다 구획 경로 머리말, 판정은 답이 든 청크로 | 모양만 본다. 허락 카드에 실제 규칙으로 센 청크 수와 비용 |
| LLM 도우미 | 진단을 읽고 흐름 순서대로 고치고 보고로 끝남 | 싼 판단부터, 모두 되돌린다 |
| 남은 것 · AI로 고치기 | 끝난 뒤 남은 문제를 지금 진단으로 다시 세어 세 묶음으로(AI로 고칠 수 있음 · 직접 권장 · AI로 못 고침) | 사람이 고른 것만 |
| 새 문장 · 질의 만들기 | LLM이 만들고 근접 거르기 · 판정 모델 확인을 통과한 것만 | 만든 데이터는 드러낸다 |
| 데이터 추가 | 흐름을 처음부터 다시 잰다. 질의는 더한 문서에만 만들고, 늘어난 문서 풀로 모든 질의의 오답을 다시 찾는다 | 닿을 때 잰다 |
| 내보내기 | 학습 · 평가 · 코퍼스 파일, 출처 칸, 교사 점수 | 나누지 않는다, 만든 데이터는 드러낸다 |

### 도우미가 지킬 일곱 가지

도우미는 채팅이 아니라 **스스로 묻고 답하며 일하는 일꾼**이고, 그 말을 창에 실시간으로 보입니다.
모든 모듈의 도우미는 같은 엔진 위에서 다음을 지킵니다.

1. **규칙 먼저.** 판단이 필요 없는 고치기는 LLM의 도구로 주지 않고 단계 처음에 스스로 합니다. 남은 애매한 것이 없으면 LLM을 부르지 않습니다.
2. **닿을 때 잰다, 흐름 순서.** 단계에 닿은 그때 재서 돌지 정합니다. 순서는 LLM이 아니라 모듈이 정합니다.
3. **문.** 새 데이터를 만들거나 다음 흐름으로 넘어가기 전에 앞 단계들을 다시 잽니다. 심각이 남으면 묻지 않고 막습니다.
4. **보고로 끝낸다.** 처음 → 끝 진단, 고친 검사, 바꾼 수, 비용. 허락을 기다리며 붙잡지 않습니다.
5. **새로 만든 데이터는 가려 둔다.** 출처로 표시하고, 이미 있는 것과 뜻이 거의 같으면 버립니다.
6. **새 항목은 뜻 분석을 다시 만든 뒤 본다.** 분석에 없는 항목이 생기면 분석부터 다시 만들고 그 단계부터 이어 돕니다.
7. **남은 것은 사람이 골라 AI로 고친다.** 처음엔 아무것도 고르지 않은 채로 보입니다.

## 4. 규칙: 사람과 AI가 함께 만드는 방법

### 한 곳에 적는다

규칙의 원본은 작업 규칙 파일 하나입니다. AI는 일할 때마다 이 파일을 읽고 따르며, 구조나 결정이 바뀌면 코드와 함께 이 파일을 고칩니다.
공개할 만한 원칙이 바뀌면 이 문서도 함께 고칩니다.
사람의 선호와 그 이유(왜 그렇게 정했나)는 AI의 대화 사이 기억에 남겨, 다음 대화에서도 같은 실수를 되풀이하지 않게 합니다.

### 구조

코드를 어디에 두는지(네 층 · 경계 · import 방향 · 파일마다 한 가지 일 · 모듈 붙이기)는 가장 중요해서 [1장](#1-아키텍처-층과-경계)에 따로 적었습니다.

### 이름: 한 뜻에 한 단어

- 한 가지 뜻은 백엔드 · 화면 · DB · 테스트 · 문서에서 같은 단어로 부릅니다. 분류 모듈은 어디서나 `classification`입니다.
- 줄임말을 새로 만들지 않습니다.
- 식별자는 영어, 주석 · 사용자에게 보이는 말은 한국어입니다. 새 용어는 한국 현업에서 쓰는 말을 먼저 찾습니다.
- 다른 프로젝트의 관례를 가져오지 않고, DENT 안에서 일관된 기준을 세웁니다.

### 코드: 사람이 읽는 코드

AI가 쓴 코드도 결국 사람이 읽고 고칩니다. 그래서 읽는 사람을 위한 자리를 정해 둡니다.

- 영리한 추상화보다 평범하게 읽히는 코드를 씁니다.
- 파일 맨 위에는 그 파일이 하는 일을, 공개 함수에는 무엇을 돌려주고 어떤 예외를 내는지를 한 줄로 적습니다.
  표 · 입출력 모양의 칸마다 바로 위에 설명 주석을 답니다.
- 주석은 코드를 되풀이하지 않고, 코드만 봐서는 알 수 없는 **이유**를 씁니다(N+1 방지, 동률 정렬, 동시 요청 등).
- 매직 넘버 대신 이름 있는 상수에 이유를 적고, 뜻이 바로 드러나지 않는 조건은 이름 있는 변수로 뺍니다.
- 식별자는 영어, 주석 · 설명 · 사용자에게 보이는 말은 한국어입니다. 한 줄은 100자까지, 모양은 ruff에 맡깁니다.
- 수백만 건을 다루므로 수는 SQL 집계로 셉니다.
- 규칙 위반은 사용자에게 그대로 보여 줄 한국어 문장의 도메인 예외로 알리고, HTTP 바꾸기는 한 곳에서 합니다.
- 새 기능은 아래층부터 만듭니다: 표 → 마이그레이션 → 입출력 모양 → 업무 규칙 → API → 작업 → 테스트 → 화면.

### 화면: 제품 수준으로

- 데모처럼 보이는 화면은 받아들이지 않습니다. 앱 틀 · 일정한 여백과 글자 크기 · 어두운 테마를 늘 함께 맞춥니다.
- 색은 강조 · 상태(초록 · 호박 · 빨강) · 회색뿐입니다.
- 폭의 경계는 px가 아닌 rem으로, 창 폭이 아닌 부품이 놓인 칸의 폭으로 잽니다. 그래야 확대 · 해상도가 달라도 같게 바뀝니다.
- 화면 방향을 크게 바꿀 때는 실제 데이터로 시안을 2~3개 먼저 만들어 고른 뒤에 구현합니다.
- 아직 기능이 없는 버튼은 표시해 두고 아무 일도 하지 않게 둡니다.

### 테스트

- 본문은 `준비 / 실행 / 확인`, 정상 경로만큼 규칙 위반(404 · 409 · 422 · 502)도 봅니다.
- 외부 서버(임베딩 · 판정 모델 · LLM · 허깅페이스)는 가짜 응답으로 대신합니다.
- 테스트는 전용 DB만 쓰고, 개발 DB에는 테스트 데이터를 넣지 않습니다.
- 내장 예시 데이터에는 문제를 정해진 수만큼 심고 정답지를 함께 둡니다. 테스트는 진단이 정답지의 수를 찾는지 봅니다.

### 사람과 AI의 약속

AI에게 코드를 맡길 때 가장 자주 부딪히는 곳은 코드가 아니라 **일하는 방식**입니다. DENT는 다음을 약속으로 둡니다.

- **묻는 것:** 요청하지 않은 변경, 되돌리기 어려운 일(개발 DB 바꾸기 · 서버 다시 실행 · 커밋)은 먼저 묻습니다. 커밋은 요청할 때만 합니다.
- **조사와 실행을 가른다:** "알아봐"는 조사만입니다. 설치 · 내려받기 · 실행이 도움이 될 것 같으면 결과를 먼저 알리고 묻습니다.
- **비밀은 밖으로 내지 않는다:** 설정 파일과 API 키는 출력하지도 커밋하지도 않습니다. 화면과 로그에도 키를 싣지 않습니다.
- **로컬에 둔다:** 개발 문서와 시안은 이 PC의 로컬 파일로 만들어 브라우저로 봅니다. 외부 서비스에 올리지 않습니다.
- **있는 그대로 알린다:** 실패는 실패로, 건너뛴 것은 건너뛰었다고, 다 된 것은 다 됐다고 말합니다.
- **언어:** 답과 문서는 한국어입니다.

### 규칙은 사고에서 나온다

대부분의 규칙은 미리 설계한 것이 아니라 실제로 겪은 일에서 나왔습니다. 몇 가지 예입니다.

| 겪은 일 | 생긴 규칙 |
|---|---|
| 심각한 문제가 남았는데 도우미가 새 데이터 만들기로 넘어갔다 | 도우미의 **문**: 앞 단계를 다시 재서 심각이 남으면 막는다 |
| 시험 데이터(뉴스 · 법령)에 맞춰 전처리 규칙을 짜려 했다 | **규칙은 모양만 본다**, 시험 데이터는 보기일 뿐 |
| 공통 기능(파일 읽기)을 한 모듈 안에 넣었다 | 두 모듈 이상이 쓰면 **system에 한 번만** |
| 다른 프로젝트의 폴더 이름을 가져왔다 | **DENT 안의 기준**으로 정한다 |
| "방법을 알아봐"에 모델을 내려받아 설치까지 했다 | **"알아봐"는 조사만** |
| 판정 모델 하나로 참 정답을 오답으로 바꾸고 답이 없는 문서를 정답으로 붙였다 | 정답을 바꾸는 판단은 **판정 모델과 LLM이 같을 때만** |
| 허락 카드의 청크 수 어림(56)과 실제(519)가 크게 달랐다 | 어림은 **실제 규칙으로 나눠 본 값**으로 |
| 되돌렸더니 판정의 충돌 표시와 출처가 사라졌다 | 되돌리기는 **줄의 상태 전체**를 남기고 돌린다 |

## 5. 검증: 믿지 말고 잰다

기능 테스트가 모두 통과해도 결과 데이터가 좋다는 보장은 없습니다. DENT는 결과 데이터를 따로 잽니다.

1. **문제를 심은 데이터.** 내장 예시(분류 2 · 검색 4)와 따로 만든 잡음 데이터에 오라벨 · 중복 · 충돌 · 반복 서명 · 깨진 글자 · 긴 문서 · 거짓 오답 같은 문제를 정해진 수만큼 심고 정답지를 둡니다.
2. **처음부터 끝까지.** 실제 임베딩 · 판정 모델 · LLM으로 가져오기 → 진단 → 뜻 분석 → 도우미 → AI로 고치기 → 데이터 추가 → 내보내기를 사람이 쓰는 순서 그대로 돌립니다. 도우미의 허락 카드는 사람처럼 비용을 보고 답합니다.
3. **정답지와 대조.** 심은 문제를 몇 개 찾고 몇 개를 옳게 고쳤는지, 고치다 멀쩡한 데이터를 망가뜨리지 않았는지 셉니다.
4. **따로 된 검증기.** 내보낸 파일만 읽고 앱 코드는 쓰지 않습니다. 빈 글 · 깨진 글 · 중복 · 같은 문장 다른 라벨 · 정답이자 오답 · 정답과 거의 같은 오답 · 문맥 의존 질의 · 남은 연락처 · 오답 수 · 평가 파일 정합을 잽니다.
   판정 모델도 틀리므로, 판정 모델이 문제라고 한 표본만 LLM에 다시 묻고 **둘이 같을 때만** 문제로 셉니다.
5. **고치고 다시 만든다.** 찾은 문제는 코드를 고치고 테스트를 더한 뒤, 데이터를 되돌리거나 다시 넣어 처음부터 다시 돌려 확인합니다.

이 과정에서 나온 결정 가운데 아직 정하지 않은 것(판정 모델만으로 받는 제안을 더 줄일지, 교사 점수를 기본으로 넣을지 등)은
작업 규칙의 "아직 정하지 않은 것"에 남겨 두고, 정하면 규칙과 이 문서를 함께 고칩니다.
